# TgVault

Локальный экспортёр Telegram-каналов и чатов. Забирает историю выбранного диалога через
MTProto (Telethon, обычный пользовательский аккаунт — не бот), складывает сообщения и метаданные
в MySQL, скачивает медиа на диск по одной из восьми стратегий раскладки и собирает результат
в самодостаточный архив: `manifest.json`, дампы в JSON/JSONL/CSV/TXT и офлайновый HTML-просмотрщик.
Инструмент для разработчика или владельца канала, которому нужна полная, воспроизводимая копия
переписки на своей машине, а не разовый дамп из официального клиента.

## Возможности

| Что | Подробности |
|---|---|
| Несколько аккаунтов | Каждый аккаунт хранит свои `api_id`/`api_hash`, сессию и весь архив; данные аккаунтов изолированы через `account_id`, удаление аккаунта каскадно сносит его чаты, сообщения и файлы |
| Вход по QR | `tg://login?token=…`, автообновление протухшего токена, ожидание сканирования в фоновой задаче |
| Вход по телефону | `send_code_request` → `sign_in`, распознаются типы кода (`app`, `sms`, `call`, `flash_call`, `missed_call`, `email`, `fragment`, `firebase`) |
| Облачный пароль 2FA | Отдельное состояние `password_required` — одинаково после кода и после QR, с подсказкой `password_hint` |
| Прокси | `socks5://`, `socks4://`, `http://` на аккаунт |
| Полный набор медиа | photo, video, **video_note («кружочки»)**, voice, audio, document, sticker, animation (GIF) |
| 8 стратегий раскладки | `flat`, `by_type`, `by_date`, `by_date_type`, `by_type_date`, `by_sender`, `by_album`, `by_size` |
| Шаблон имени файла | `{id} {date} {time} {datetime} {name} {ext} {kind} {sender} {chat} {album}` |
| Инкрементальный экспорт | По умолчанию догружает только сообщения новее максимального `tg_message_id` в базе |
| Возобновляемые задачи | Пауза / возобновление / отмена; после перезапуска приложения незавершённые задачи автоматически возвращаются в очередь |
| Архив в MySQL | Уже скачанное не качается повторно (`skip_existing`), пересборка отчётов идёт из базы без обращения к Telegram |
| Redis как шина событий | pub/sub для прогресса; при недоступности — in-memory fallback, приложение работает |
| Живой прогресс | WebSocket `/ws`: `job_progress`, `job_event`, `auth_state`, `chat_sync`, `log`, `account` |
| Офлайновый просмотрщик | `index.html` + `assets/data.js`, открывается двойным кликом с `file://`, «кружочки» играют в круглом контейнере |
| Форматы выгрузки | `json`, `jsonl`, `csv`, `txt`, `html` — любая комбинация |
| Шифрование сессий | Telegram-сессии лежат в БД зашифрованными Fernet |

## Быстрый старт

Требуется: **Docker Desktop** (для MySQL 8 и Redis 7), **Python ≥ 3.10**, **Node.js ≥ 18**.

```bash
./start.sh
```

Скрипт сам создаст `.env`, поднимет контейнеры, соберёт venv, установит зависимости, соберёт
фронтенд и запустит backend. Когда в консоли появится баннер — открывайте:

```
http://127.0.0.1:8077
```

Пользователям Windows: запускать **из Git Bash** (входит в Git for Windows). `cmd.exe` и
PowerShell не выполнят `./start.sh`.

Остановить всё:

```bash
./stop.sh
```

Подробности, флаги и ручной запуск без `start.sh` — в [docs/SETUP.md](docs/SETUP.md).

## Где взять `api_id` и `api_hash`

1. Откройте <https://my.telegram.org> и войдите по номеру телефона (код придёт в Telegram).
2. Выберите **API development tools**.
3. Заполните форму приложения (`App title`, `Short name`; платформа — любая, например `Desktop`).
4. Скопируйте **App api_id** (число) и **App api_hash** (32 hex-символа).

Одна пара `api_id`/`api_hash` рассчитана на **приложение, а не на номер**: её штатно можно
использовать для нескольких аккаунтов сразу — именно так работают официальные клиенты.
Выдаётся пара по номеру телефона (один номер = один `api_id`), но использовать её можно с любыми
аккаунтами. Никогда не берите чужой `api_id` из репозиториев и туториалов: публично засвеченные
пары постоянно тротлятся сервером (`ApiIdPublishedFloodError`), а аккаунты на них рискуют
получить бан.

Пару можно ввести в UI при создании аккаунта либо задать один раз в `.env`
(`TGV_DEFAULT_API_ID` / `TGV_DEFAULT_API_HASH`) — тогда она подставится по умолчанию.

## Безопасность и приватность

* Строки сессий Telegram (`accounts.session_enc`) шифруются Fernet. Ключ выводится из мастер-секрета
  в **`data/secret.key`** (или `TGV_SECRET_KEY` в `.env`) — файл создаётся автоматически при первом запуске.
* Всё работает локально: backend слушает `127.0.0.1`, MySQL и Redis подняты в docker на локальных портах.
  Наружу ничего не отправляется, телеметрии нет.
* `.env`, `data/` и `secret.key` перечислены в `.gitignore`.
* **`data/secret.key` вместе с дампом БД = полный доступ к аккаунту Telegram.** Расшифрованная строка
  сессии позволяет войти в аккаунт без кода и без пароля 2FA. Храните их как пароль; не кладите в
  общие бэкапы и не переносите на чужие машины.
* Если `secret.key` потерян или заменён, сохранённые сессии расшифровать нельзя — аккаунты просто
  потребуют повторного входа (данные архива при этом целы).
* Разлогиниться и отозвать сессию на стороне Telegram: `POST /api/accounts/{id}/logout` (кнопка в UI).

## Ограничения

* **Лимиты Telegram реальны и обойти их нельзя.** Наблюдаемый потолок для истории — примерно
  1000 сообщений за 30 секунд; чанк `iter_messages` жёстко равен 100 сообщениям за один RPC.
* **FloodWait — штатная ситуация, а не сбой.** Waits короче `TGV_FLOOD_SLEEP_THRESHOLD` (60 с)
  Telethon отсыпает сам; более длинные движок ждёт явно, пишет в таймлайн задачи
  «Ограничение Telegram (FloodWait): пауза N с» и продолжает. Ожидание дольше 1 часа считается
  бессмысленным — задача останавливается с ошибкой.
* **Большие каналы качаются часами.** Реалистичная скорость одного соединения Telethon —
  0.3–0.5 МБ/с без `cryptg` и 1–2 МБ/с с ним. Канал на 200 000 сообщений с медиа — это работа
  на ночь, а не на пять минут.
* **Параллельность ограничена сверху.** `concurrency` в опциях экспорта — 1..16, по умолчанию 4.
  Задирать её опасно: главный риск не FloodWait, а `AuthKeyDuplicatedError` — сервер уничтожает
  ключ сессии, и аккаунт приходится авторизовывать заново.
* **Одна строка сессии — одно живое подключение.** Не запускайте вторую копию TgVault на той же
  БД и не используйте ту же сессию в другом инструменте.
* **Takeout-режим (`use_takeout`) не снижает флуд-лимиты.** Telegram нигде этого не обещает; это
  механизм авторизации массового экспорта. Первая инициализация обычно упирается в
  `TakeoutInitDelayError` — это 24-часовая **задержка безопасности**, а не флуд-штраф; её можно
  пропустить, подтвердив экспорт на другом устройстве. По умолчанию опция выключена.
* **Telegram Premium поднимает лимиты на загрузку, но здесь это мало что меняет** — узкое место
  в одном соединении Telethon. Заливка файлов инструменту не нужна: TgVault только скачивает.
* Экспорт делается от лица пользовательского аккаунта: доступны только те чаты, которые видит
  сам аккаунт. Закрытый канал без подписки прочитать нельзя.
* Миграций (Alembic) нет: схема создаётся `create_all` и дополняется мягкими миграциями
  в `bootstrap.py`. См. [docs/DATABASE.md](docs/DATABASE.md).
